# lkdr-api — пакет изменений

Этот ZIP содержит комплект, который получает полный исходный проект `jfk9w-go/lkdr-api` из GitHub и накладывает изменения.

## Что меняется

- Убирается зависимость примера от RuCaptcha.
- CAPTCHA вводится вручную только если библиотеке действительно понадобится новая авторизация.
- Существующий `tokens.json` с плоской структурой читается без повторного входа.
- Файл токенов и экспорт JSON создаются с правами `0600`, каталог — `0700`.
- Чеки загружаются страницами по 50 записей до `hasMore=false`.
- Дубликаты удаляются по `receipt.key`.
- Для каждого чека запрашиваются подробности `FiscalData`.
- Экспорт сохраняется после каждой страницы и каждого чека, чтобы не потерять уже полученные данные.
- Добавлен `update_lkdr_token.py` для обновления access-токена из HAR Firefox.

## Установка на FreeBSD

Распакуй ZIP. Перейди в распакованный каталог и запусти:

```sh
sh ./install.sh "$HOME/lkdr-api"
```

Скрипт клонирует полный upstream-проект в указанный каталог, применит overlay и выполнит `go mod tidy`.

## Запуск

Задай переменные окружения:

```sh
export LKDR_PHONE="твой_телефон"
export LKDR_TOKENS_FILE="$HOME/.local/share/lkdr/tokens.json"
export LKDR_DEVICE_ID="твой_sourceDeviceId"
export LKDR_USER_AGENT="строка navigator.userAgent из Firefox"
export LKDR_OUTPUT_FILE="$HOME/receipts.json"
```

Затем:

```sh
cd "$HOME/lkdr-api"
go run ./example
```

Если в файле уже есть действующий access token, скрипт использует его. Он не должен запускать SMS/CAPTCHA-процедуру до истечения/непригодности сохранённых токенов. Если потребуется новая авторизация, CAPTCHA и SMS-код запрашиваются интерактивно.

## Обновление токена из HAR

```sh
python3 ./tools/update_lkdr_token.py "$HOME/Downloads/имя-файла.har" --phone "$LKDR_PHONE"
```

HAR содержит заголовки авторизации и другие чувствительные данные. Не публикуй его и не отправляй посторонним.

Если в HAR найден только истёкший токен, скрипт откажется его сохранять. Отсутствие refresh token означает, что автоматически продлить сессию нельзя.

## Формат экспорта

`receipts.json` содержит:
- `listComplete` — полностью ли получен список чеков;
- `detailsComplete` — удалось ли получить подробности каждого чека;
- `receipts[]` — объект `receipt`, `fiscalData` и `detailError` при ошибке получения подробностей.

## Важно

Это комплект изменений поверх текущей ветки `master` upstream-репозитория, а не проверенная сборка под все версии Go. После установки выполни:

```sh
go test ./...
go run ./example
```
